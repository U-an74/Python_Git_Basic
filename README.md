## ☑️ 프로그램 설명

### 1. 개요
- 프로그램명: 프롬프트 금고 (prompt-vault) 
- 터미널에서 메뉴 번호를 입력해 기능을 선택하는 콘솔 기반 python 도구
- 자주 쓰는 AI 프롬프트를 저장하고 관리하는 프로그램입니다.

### 2. 기능 목록
- CRUD
1. 프롬프트 추가 (Create)
2. 프롬프트 목록 (Read) 
3. 프롬프트 수정 (Update)
4. 프롬프트 삭제 (Delete)
- Detail
5. 프롬프트 상세 보기
6. 카테고리별 조회
7. 프롬프트 검색
8. 즐겨찾기 추가/해제
9. 즐겨찾기 목록
10. 종료
- Git을 이용한 버전 관리

### 3. 실행 방법
- Python 설치(3.14.7버전 권장)
- 저장소 클론: `git clone https://github.com/본인계정/prompt-vault.git`
- 실행: `python main.py`

### 4. 카테고리 종류
1. 텍스트 생성: 텍스트 기반 문서 생성 프롬프트
2. 멀티모달 생성: 이미지/동영상 등 콘텐츠 생성 프롬프트
3. 기타: 위 카테고리에 속하지 않는 프롬프트 일체

## ☑️ 설계 문서

### 1. 커밋 전략
- **기준**: 기능 단위로 커밋 (하나의 커밋 = 하나의 기능/변경)
- **브랜치 전략**: 기능별 브랜치 생성 → 구현 완료 후 main 병합

**커밋 메시지 규칙**
| 태그 | 의미 | 예시 |
|------|------|------|
| `feat:` | 새 기능 추가 | `feat: 즐겨찾기 토글 기능 추가` |
| `fix:` | 버그 수정 | `fix: 삭제 인덱스 오류 수정` |
| `docs:` | 문서 수정 | `docs: README.md 업데이트` |
| `refactor:` | 코드 구조 개선 | `refactor: 함수 분리 구조 적용` |

**브랜치 분리 기준**
- 기능 하나 = 브랜치 하나
- 브랜치명: `feature/기능명` 형식 사용
- 병합 시점: 해당 기능 구현 완료 + 동작 확인 후 main에 병합

```
feature/category-filter  → main 병합 (카테고리 조회 완성 후)
feature/search           → main 병합 (검색 기능 완성 후)
feature/favorites        → main 병합 (즐겨찾기 완성 후)
```

### 2. 데이터 구조 선택 이유

**선택: 리스트(list) + 딕셔너리(dict) 조합**

```python
prompts = [
    {"id": 1, "title": "제목", "category": "기타", "content": "내용", "favorite": False}
]
```

| 구조 | 장점 | 단점 |
|------|------|------|
| **리스트** | 순서 유지, 반복 처리 쉬움 | 특정 항목 검색 시 전체 순회 필요 |
| **딕셔너리** | 필드명으로 직관적 접근 가능 | 키 이름 오타 시 오류 발생 가능 |
| **조합 선택 이유** | 여러 프롬프트를 순서대로 관리하면서 각 항목의 속성을 명확히 표현 가능 | - |

### 3. 메인 루프 설계 의도

**while True 반복문 사용 이유**
- 사용자가 명시적으로 종료를 선택할 때까지 프로그램을 계속 실행
- 메뉴 기반 콘솔 프로그램의 표준 패턴

```python
def main():
    while True:          # 무한 반복 → 메뉴 계속 표시
        show_menu()
        choice = input()
        if choice == "10":
            break        # 종료 조건: 사용자가 10번(종료) 선택 시 루프 탈출
```

**종료 조건**: 메뉴에서 `10. 종료` 선택 시 `break`로 루프 탈출 후 프로그램 종료

### 4. 데이터 영속화 방안

> ⚠️ 현재 버전: 메모리(리스트)에만 저장 → 프로그램 종료 시 데이터 초기화

**향후 적용 예정 방식: JSON 파일 저장**

| 방식 | 장점 | 단점 | 선택 여부 |
|------|------|------|----------|
| **JSON** | 딕셔너리 구조와 호환, 사람이 읽기 쉬움 | 대용량 비효율 | ✅ 예정 |
| **CSV** | 표 형태 데이터에 적합 | 중첩 구조 표현 어려움 | ❌ |
| **DB(SQLite)** | 검색/정렬 강력 | 설정 복잡 | 추후 고려 |

```python
# 향후 구현 방향
import json
def save_data(prompts):
    with open("prompts.json", "w", encoding="utf-8") as f:
        json.dump(prompts, f, ensure_ascii=False, indent=2)
```

### 5. 중복 제목 처리 정책

**현재 정책: 중복 허용**
- 같은 제목의 프롬프트 여러 개 저장 가능
- ID로 각 항목을 구분하므로 기능상 문제 없음

**향후 개선 방향**
```
중복 제목 입력 시 →  "이미 같은 제목이 있습니다. 계속 저장할까요? (y/n)"
                      y 선택 → 저장 허용
                      n 선택 → 제목 재입력 요청
```

### 6. 병합 충돌 해결 절차

**발생 원인**
- 같은 파일의 같은 줄을 서로 다른 브랜치에서 수정 후 병합 시 발생

**해결 순서**
```
1. 충돌 발생 확인
   git merge feature/브랜치명
   → CONFLICT 메시지 출력

2. 충돌 파일 열어서 수동 수정
   <<<<<<< HEAD
   (현재 브랜치 내용)
   =======
   (병합할 브랜치 내용)
   >>>>>>> feature/브랜치명

3. 원하는 내용만 남기고 충돌 표시 삭제

4. 수정 후 커밋
   git add 파일명
   git commit -m "fix: 병합 충돌 해결"

5. 검증
   python main.py 실행 → 정상 동작 확인
```

> 📌 본 프로젝트에서는 브랜치별 작업 범위를 명확히 분리하여 충돌 없이 병합 완료
